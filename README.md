# 图纸审查如何建立评测

这是一个个人方法演示作品：用完全合成的图纸信息，演示如何评价审查意见的正确性、对象定位、证据支持和证据不足时的处置。读者可以在不访问内部工程资料、不调用模型API的条件下复现结果，并把自己的模型输出接入同一评测器。

Drawing Review Evaluation：a reproducible synthetic benchmark for finding matching, evidence attribution, abstention and evaluation gates. Python standard library only. No real engineering drawings or LLM calls.

项目当前实现的是结构化输入上的确定性基线与评测协议。SVG用于展示；没有实现从真实CAD或扫描图纸提取信息，也没有验证大模型审图能力。

## 五分钟运行

需要Python 3.9及以上版本，仅使用标准库。

```bash
python3 -m unittest -v test_demo.py
python3 demo.py run --output build
```

生成96个案例、96张示意SVG、真值、两组预测、逐案例报告和SHA-256复现记录。`build/`是可重建产物，不纳入版本管理。已有结果摘要见[results](results/)，样例见[examples](examples/)。

## 问题与方法

只报一个“准确率”会混淆漏检、误报和证据不足。一个正确的审查意见至少需要对应正确的规则和对象，并引用足够的输入证据；证据缺失时，应输出“待人工复核”，而不是“审查通过”。

本作品设计两条自定义演示规则：标注尺寸经单位换算后应与结构化几何长度一致；构件应处于指定演示图层。规则编号使用`DEMO_`前缀，与任何真实行业标准无关。具体容差和图层名称都是演示设置。

16个图纸族各有6个变体：正常尺寸、错误尺寸、等价混合单位、错误单位、错误图层、尺寸证据缺失。前8族开发、后8族测试；同族变体不跨划分。输入不包含注错类别、真值或图纸族标识。生成器按注错计划建立真值，基线只接收输入。所有案例公开后不构成保密盲测。

## 已运行的验证结果

测试集48例，含24条真实演示问题、16例无问题输入及8例证据不足输入。

| 指标 | 简单基线 | 带证据检查的基线 |
|---|---:|---:|
| 意见精确率 | 50.0% | 100.0% |
| 意见召回率 | 33.3% | 100.0% |
| 有完整指定证据的召回率 | 33.3% | 100.0% |
| 正常案例误报率 | 50.0% | 0.0% |
| 证据不足案例正确转人工率 | 0.0% | 100.0% |
| 自动作出完整判断的覆盖率 | 100.0% | 83.3% |

简单基线故意省略单位换算、图层检查和证据缺失处理，用来展示指标能暴露什么问题；它不代表任何商业产品或大模型。改进基线与数据均按同一组简单规则设计，满分只证明本作品内的规则实现与评测流程一致，不能推出对未知图纸或真实工程的泛化能力。

12项回归测试涵盖重复意见、漏交预测、错误证据、未知案例、全量转人工等反例；意见命中但引用无关证据时，仍不能通过演示验收门槛。详见[评测协议](docs/评测协议.md)。

## 接入自己的模型

向模型提供`build/inputs.json`中测试划分的案例及[协议](docs/评测协议.md)；不要提供`gold.json`或测试注错类别。将预测保存为JSON列表，再执行：

```bash
python3 demo.py evaluate \
  --inputs build/inputs.json \
  --gold build/gold.json \
  --predictions your_predictions.json \
  --split test \
  --output build/report_model.json
```

当前未运行任何模型实验。真实模型实验还需记录模型标识、提示词、推理参数、原始响应、失败与超时、费用及重复运行差异；不能只提交挑选过的成功案例。

## 局限与下一步

输入已经结构化，绕过了CAD解析、OCR、对象关联和图纸专业理解。样本只有单构件、单故障和两条规则；真值由程序生成，未经独立专业评审。证据评分只核对指定对象ID的集合，不验证自然语言解释是否成立。相同族变体存在相关性，报告中的逐案例Wilson区间只是计算示例，不能作为真实独立样本置信结论。

下一步先增加复合错误、正确但非常规表达及图纸缺页案例，再请独立审阅者确认规则与标签，最后用按项目分组的外部数据评价真实模型。演示门槛与工程验收分开：当前所有报告均标记`production_acceptance=NOT_ESTABLISHED`。
